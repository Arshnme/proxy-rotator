# Proxy rotator (gemini rotator) — bypass google 403 error & location is not supported — Route your application's traffic through V2Ray configs

**دور زدن خطای ۴۰۳ گوگل و «location is not supported» — همچنین با این اسکریپت می‌توانید ترافیک برنامه‌تان را از طریق کانفیگ‌های V2Ray عبور بدید.**

### مشکل دقیقا کجاست؟

وقتی درخواستی به API جمنای می‌رسد، گوگل کشور درخواست را از روی **آی‌پی مبدأ اتصال** تشخیص می‌دهد. اگر آن کشور در لیست کشورهای پشتیبانی‌شده نباشد، خطای `User location is not supported for the API use.` (کد HTTP ۴۰۰ با وضعیت `FAILED_PRECONDITION`) برمی‌گردد. این خطا ربطی به کلید API ندارد. (پیام‌هایی مثل «not available in your country» مربوط به اپ وب گوگل است، نه این API.)

حتی روی سروری که در یک کشور پشتیبانی‌شده اجاره شده، دو دلیل رایج باعث این خطا می‌شود:

1. **خروج درخواست از مسیر IPv6.** اغلب سرورها هم IPv4 دارند هم IPv6 و بسیاری از برنامه‌ها و پنل‌ها IPv6 را ترجیح می‌دهند. موقعیت جغرافیایی رنج‌های IPv6 دقت کمتری دارد و ممکن است سروری که با IPv4 درست شناخته می‌شود، با IPv6 به‌عنوان منطقه‌ی پشتیبانی‌نشده یا نامشخص دیده شود.
2. **آی‌پی مبدأ اشتباه.** روی سروری که چند آی‌پی دارد، سیستم‌عامل ممکن است آی‌پی دیگری را برای اتصال خروجی انتخاب کند.

راه‌حل: **ترافیک جمنای را فقط با IPv4 و از یک آی‌پی مشخص سرور خارج کنیم.** در Xray (هسته‌ی 3x-ui و x-ui و مرزبان) این کار با یک outbound از نوع `freedom` انجام می‌شود:

```json
{
  "tag": "ipv4-out",
  "protocol": "freedom",
  "sendThrough": "IPv4-سرور",
  "settings": { "domainStrategy": "UseIPv4" }
}
```

- `freedom`: ترافیک مستقیم به مقصد می‌رود.
- `UseIPv4`: نام دامنه فقط به IPv4 ترجمه می‌شود و IPv6 هرگز استفاده نمی‌شود.
- `sendThrough`: اتصال خروجی به همین آی‌پی سرور وصل (bind) می‌شود تا گوگل دقیقاً همین آی‌پی را ببیند.

> **نکته‌ی مهم:** این روش آی‌پی شما را عوض یا مخفی نمی‌کند. فقط مطمئن می‌شود گوگل «آی‌پی IPv4 واقعی و درست‌شناخته‌شده‌ی سرور» را می‌بیند، نه یک IPv6 با موقعیت اشتباه. پس خودِ سرور باید در کشور پشتیبانی‌شده باشد و رنج IPv4 آن بلاک نشده باشد. اگر IPv4 خودش بلاک باشد، مسیر `direct4` در داشبورد مرده نشان داده می‌شود و باید از پراکسی‌ها در حالت `hybrid` استفاده کنید.



### اسکریپت چطور کار می‌کند؟

- تابع `ensure_builtin()` در `rotator/app.py` هنگام شروع، outbound فریدوم با `UseIPv4` و `sendThrough` را می‌سازد و به‌عنوان مسیر `direct4` ثبت می‌کند. آی‌پی IPv4 سرور با `detect_ipv4()` خودکار پیدا می‌شود (یا در `ipv4_send_through` دستی می‌دهید).
- تابع `_build()` در `rotator/xray.py` برای هر مسیر یک inbound محلی (SOCKS روی `127.0.0.1`) و یک قانون مسیریابی «inboundTag به outboundTag» می‌سازد، یعنی همان قانونی که در پنل دستی اضافه می‌کردید. نیازی به تنظیم ترتیب قوانین یا ری‌استارت نیست.
- گیت‌وی (`:8787`) هر درخواست جمنای را با همان مسیر و هدر و کلید، از طریق `socks5://127.0.0.1:<پورت>` به این inbound می‌فرستد و از IPv4 سرور به گوگل می‌رسد.
- مسیر مرتب با خود API جمنای (`countTokens`، رایگان) تست می‌شود. اگر ارور «location not supported» یا خطای شبکه برگردد، درخواست خودکار روی مسیر دیگری تکرار می‌شود.
- `direct4` هیچ‌وقت حذف نمی‌شود و اگر موقتاً از کار بیفتد خودش دوباره زنده می‌شود. پراکسی‌های مرده یا بلاک‌شده حذف و در `data/removed.txt` آرشیو می‌شوند.

### نصب و استفاده‌ی سریع

```bash
git clone https://github.com/Arshnme/proxy-rotator.git
cd proxy-rotator
sudo bash install.sh install        # نصب (xray، venv، سرویس systemd)
bash install.sh live                # داشبورد زنده
```

سپس در ربات یا برنامه‌ی خودتان فقط آدرس پایه‌ی جمنای را عوض کنید:

```python
# قبل
https://generativelanguage.googleapis.com
# بعد
http://127.0.0.1:8787
```

با SDK رسمی:

```python
from google import genai
client = genai.Client(api_key=KEY, http_options={"base_url": "http://127.0.0.1:8787"})
```

یا اطلاعاتت را از طریق پروکسی‌هایی که اسکریپت ایجاد کرده است سمت جمنای ارسال کنید :

```python
# socks5 proxy
socks5://127.0.0.1:1080
# HTTP proxy
http://127.0.0.1:8118
```



حالت‌های مختلف اسکریپت (`egress_mode`):

| حالت | توضیح |
| --- | --- |
| `ipv4` | فقط IPv4 خود سرور (حالت پیش‌فرض نصب شده — در این حالت دیگر نیازی به وارد کردن کانفیگ v2ray در داخل proxies.txt نیست ). |
| `hybrid` | IPv4 آیپی مستقیم سرور و پراکسی‌ها با هم کار می‌کنند؛ اگر یکی از کار بیفتد دیگری جایگزین می‌شود. |
| `proxies` | فقط پراکسی‌ها. |

تغییر حالت به‌صورت زنده: `bash install.sh mode hybrid`

> در صورتی که حالت پیش‌فرض اسکریپت مشکل "در دسترس نبودن در لوکیشن" را حل نکرد، پروکسی‌های v2ray خودتون رو داخل proxies.txt قرار بدید و به مود پروکسی سوییچ کنید تا درخواست‌ها  از طریق کانفیگ v2ray ای که اضافه کردید، به سمت جمنای یا سرویس‌های گوگل یا سایر سرویس‌هایی که نیاز به پروکسی دارند فرستاده شود.، 

### ساختار پروژه

```text
gemini-proxy/
├── README.md                  # همین راهنما
├── LICENSE                    # لایسنس MIT
├── requirements.txt           # وابستگی‌ها: aiohttp، aiohttp-socks
├── config.json                # تنظیمات اصلی (پورت‌ها، حالت خروج، استراتژی، تایم‌اوت‌ها)
├── proxies.txt                # لیست پراکسی‌ها (در حالت ipv4 اجباری نیست)
├── install.sh                 # نصب و مدیریت: راه‌اندازی سرویس، داشبورد زنده، تغییر حالت
├── gemini_rotator.py          # نقطه‌ی ورود سازگاری با نام قدیمی
├── xray                       # باینری Xray (توسط install.sh دانلود می‌شود)
├── geoip.dat                  # دیتاست‌های همراه Xray (این پروژه از آن‌ها استفاده نمی‌کند)
├── geosite.dat
├── bin/
│   └── xray                   # نسخه‌ی باینری که اسکریپت اجرا می‌کند
├── rotator/                   # کد اصلی برنامه
│   ├── __init__.py            # نسخه‌ی برنامه (2.0.0)
│   ├── __main__.py            # ورودی `python -m rotator`
│   ├── app.py                 # هماهنگ‌کننده: بارگذاری پراکسی‌ها، شاردها، هلس‌چک، سرویس‌دهی
│   ├── admin.py               # API محلی ادمین (برای CLI و داشبورد)
│   ├── cli.py                 # خط فرمان: status، list، add، remove، recheck و ...
│   ├── gateway.py             # گیت‌وی معکوس :8787 و پروکسی‌های HTTP :8118 و SOCKS5 :1080
│   ├── parsers.py             # پارسر همه‌کاره‌ی لینک‌های پراکسی
│   ├── pool.py                # استخر پراکسی: امتیازدهی، استراتژی‌ها و شمارش خطاها
│   ├── util.py                # مسیرها، تنظیمات، لاگ و ابزارهای کمکی
│   └── xray.py                # مدیریت پردازه‌های Xray (شاردها) و ساخت کانفیگ
├── tests/
│   ├── load.py                # تست بار
│   └── mockenv.py             # محیط جعلی جمنای و پراکسی برای تست یکپارچگی
├── data/                      # (در زمان اجرا ساخته می‌شود) state.json، removed.txt
├── run/                       # (در زمان اجرا) وضعیت شاردها و PIDها
└── logs/                      # (در زمان اجرا) rotator.log و xray-*.log
```
